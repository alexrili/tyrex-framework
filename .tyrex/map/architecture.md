# Architecture - Tyrex Framework

> Generated by `/tyrex-init` on 2026-03-07

## Pattern

**CLI Scaffolding Tool / Prompt Engineering Framework**

Tyrex is not a traditional application — it is a developer tooling framework distributed as an npm package. It scaffolds a `.tyrex/` directory and agent-specific command directories into target projects, providing a structured AI pair-programming workflow.

The pattern is closest to a **scaffolding generator** (like `create-react-app` or `yeoman`), combined with a **prompt engineering framework** that defines slash commands as markdown instruction files for AI agents.

## Structure

```
tyrex/
├── bin/tyrex.js              # Single-file CLI (417 lines, zero deps)
├── templates/                # Source templates (shipped with npm)
│   ├── commands/unified/     # 16 command definitions (.md)
│   ├── *.md / *.yml          # Config and doc templates
│   └── docs/                 # Empty doc scaffolds
├── .tyrex/                   # Self-hosted Tyrex instance
│   ├── TYREX.md              # Living project context
│   ├── constitution.md       # Guardrails
│   ├── tyrex.yml             # Config
│   ├── state/                # Session state (cursor.yml, tasks/)
│   ├── templates/            # User-facing doc templates
│   └── map/                  # This directory
├── .claude/commands/         # Installed commands for Claude Code
├── .opencode/commands/       # Installed commands for OpenCode
├── .cursor/rules/tyrex/      # Installed commands for Cursor
├── .codex/skills/tyrex/      # Installed commands for Codex
└── docs/                     # Project documentation
    ├── CHANGELOG.md
    ├── adrs/ rfcs/ wiki/ diagrams/
```

## Key Design Decisions

1. **Zero dependencies** — CLI uses only Node.js built-ins (`fs`, `path`, `readline`, `os`)
2. **Agent-agnostic** — One set of command definitions works across 4 AI agents
3. **Prompt engineering as code** — Commands are markdown instruction files, not executable code
4. **State via filesystem** — YAML files serve as shared memory between sessions
5. **Self-hosted** — Tyrex uses Tyrex itself (`.tyrex/` directory)
6. **Template-driven** — All output uses `{{PLACEHOLDER}}` interpolation

## Data Flow

```
User invokes slash command (e.g., /tyrex-do)
  → AI agent reads command .md file (instruction set)
  → Agent reads .tyrex/TYREX.md (project context)
  → Agent reads .tyrex/constitution.md (guardrails)
  → Agent reads .tyrex/state/cursor.yml (session state)
  → Agent performs work (code changes, commits)
  → Agent updates state files (cursor.yml, task states)
```
